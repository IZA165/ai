1.1 Systems architecture

CPU
Processes instructions to run programs, using the fetch-decode-execute cycle on repeat.
Fetch-decode-execute
Fetch: the instruction at the address in the PC is copied from RAM. Decode: the control unit works out what it means. Execute: the instruction is carried out, with the ALU doing any calculation or logic.
Components
ALU: arithmetic and logic. CU: decodes instructions and controls the flow of data. Cache: very fast memory inside the CPU for frequently used data.
Registers
PC: address of the next instruction. MAR: address being read or written. MDR: the data fetched or about to be written. ACC: stores results from the ALU.
Von Neumann
Instructions and data are stored together in main memory, in binary, and processed one after another.
CPU performance
Higher clock speed (GHz) means more cycles per second. More cores can run tasks in parallel, but only if the software uses them. Bigger cache means fewer slow trips to RAM.
Embedded systems
A computer built into a larger device to do one dedicated job, such as a washing machine, car engine controller or traffic lights.

Diagrams and worked examples

Typical exam link: CPU performance is set by clock speed, number of cores and cache size. A faster clock does not always mean a faster computer if the program cannot use extra cores or RAM is the bottleneck.

Deeper: architecture and the cycle

In Von Neumann architecture the program and its data share one memory and one set of buses. The CPU cannot fetch an instruction and data at the same moment, which limits speed (the "bottleneck").

1.2 Memory and storage

RAM and ROM
RAM is volatile, read/write, and holds running programs and data. ROM is non-volatile, read-only, and holds the boot-up instructions.
Virtual memory
When RAM is full, part of secondary storage is used as extra RAM. It is much slower, so too much use slows the computer.
Secondary storage
Needed because RAM loses data when power is off. Magnetic (HDD): cheap, large capacity, moving parts so slower and less durable. Solid state (flash): fast, silent, durable, costs more per GB. Optical (CD, DVD, Blu-ray): cheap and portable, low capacity, easily scratched. Compare on capacity, speed, portability, durability and cost.
Units
4 bits = nibble, 8 bits = byte. Then kB, MB, GB, TB, PB, each 1000 times the last.
Binary and hex
8-bit place values: 128 64 32 16 8 4 2 1. Hex uses 0-9 and A-F, and one hex digit = 4 bits (so 1111 1111 = FF = 255).
Binary addition and shifts
0+0=0, 1+0=1, 1+1=10 (write 0, carry 1). Overflow happens if the answer needs more than 8 bits. A left shift multiplies by 2 per place, a right shift divides by 2. Bits shifted off the end are lost.
Characters
ASCII has 128 characters (7 bits), shown in 8 bits in the exam. Unicode uses more bits so it covers many languages, symbols and emoji, but files are larger.
Images
Made of pixels. Resolution = number of pixels. Colour depth = bits per pixel. File size = width x height x colour depth. Metadata (e.g. dimensions) is stored too.
Sound
Sampled at regular intervals. Sample rate (Hz), bit depth and duration set quality and size. File size = sample rate x bit depth x seconds.
Compression
Lossy permanently removes data for a much smaller file (JPEG, MP3). Lossless can be rebuilt exactly (PNG, ZIP, run-length encoding).

Exam tip: Show your working for conversions and file size calculations: method marks are available.

Terms

Most significant bit (MSB): the leftmost bit, worth the most (128 in 8 bits). Least significant bit (LSB): the rightmost bit, worth 1. Text file size = bits per character x number of characters.

Denary to binary

Subtract place values from the left. 150: 128 fits (22 left), 64 no, 32 no, 16 fits (6 left), 8 no, 4 fits (2 left), 2 fits. Answer 1001 0110.

Hex conversions

Hex to denary: 3F = 3 x 16 + 15 = 63. Denary to hex: 200 / 16 = 12 remainder 8, so C8. Hex is used because it is shorter and easier for people to read and check than binary, and each digit maps to exactly 4 bits.

Convert 10110011 to denary and hex. (3 marks)

128 + 32 + 16 + 2 + 1 = 179. Nibbles 1011 and 0011 give hex B3.

Explain why a computer needs both RAM and secondary storage. (3 marks)

RAM is fast and holds the programs and data in use, but it is volatile and loses everything when power is off. Secondary storage is non-volatile so keeps files permanently, but is slower.

A 16-bit, 8 000 Hz recording lasts 20 seconds. Give the file size in bytes. (3 marks)

8 000 x 16 x 20 = 2 560 000 bits. Divide by 8 = 320 000 bytes.

Give two differences between lossy and lossless compression. (2 marks)

Lossy permanently removes data but gives a smaller file; lossless keeps all data so the original can be rebuilt exactly.

Common mistakes

  • Forgetting to divide by 8 for bytes.
  • Writing 1000 instead of 1024 only matters if the question says so. J277 uses 1000.
  • Saying RAM is "temporary storage" without saying it is volatile.
  • Leaving out carry bits when adding binary.

1.3 Networks, connections, protocols

LAN and WAN
LAN: small area, owned by one organisation. WAN: large area, uses leased telecoms lines. The internet is the biggest WAN.
Performance
Affected by bandwidth, number of devices, transmission media and errors.
Client-server and peer-to-peer
Client-server: a central server manages files, security and backup, but costs more and is a single point of failure. Peer-to-peer: devices share directly, cheaper, but harder to secure and back up.
Hardware
NIC connects a device. Switch connects devices on a LAN. Router connects networks and forwards packets. WAP gives wireless access. Media: copper Ethernet or fibre optic.
Topologies
Star: every device connects to a central switch. One cable fails, only that device is lost, but if the switch fails everything does. Mesh: devices link to several others, very reliable but expensive.
Wired v wireless
Wired: faster, more reliable, more secure. Wireless (Wi-Fi, Bluetooth): convenient and flexible, but slower, interference, easier to intercept, so use WPA2 encryption.
Addresses and DNS
IP address identifies a device on a network and can change. MAC address is fixed to the NIC. DNS turns domain names into IP addresses.
The cloud
Storage and software accessed over the internet. Pros: access anywhere, scalable, no local hardware. Cons: needs internet, ongoing cost, trust in the provider's security.
Protocols
TCP/IP: TCP splits data into packets and reassembles them, IP addresses and routes them. HTTP/HTTPS: web pages (HTTPS is encrypted). FTP: file transfer. SMTP: send email. IMAP: receive email.
Layers and packets
Layers (application, transport, internet, link) let each part be developed separately. Packets hold destination, source, packet number and data. They can take different routes and are reassembled in order.

Diagrams and worked examples

A message is split into packets. Each may take a different route through routers, so packets can arrive out of order. TCP uses the packet numbers to reassemble them and asks for any missing or corrupt packet to be resent.

DNS

The DNS is made up of many domain name servers that convert a URL into an IP address.

Hosting and the cloud

Web hosting means a company rents out server space to store websites so they are always online. Cloud computing stores data and runs software on remote servers accessed over the internet. Advantages: access from any device, no need to buy or maintain hardware, storage can grow as needed, and automatic backups. Extension: how packets travel (packet switching was removed from J277, so this is background)

  1. TCP splits the message into packets and numbers them.
  2. IP adds source and destination addresses.
  3. Each packet is passed router to router, and may take a different route.
  4. At the destination the packets are checked and put back in order using the numbers.
  5. Missing or damaged packets are requested again.

Layers (OCR requires the idea and benefits of layers, not the layer names): application (the program, e.g. browser), transport (TCP), internet (IP), link (physical network). Each layer does one job, so a layer can be changed without rewriting the others, and problems are easier to find.

1.4 Network security

Malware
Viruses attach to files, worms spread by themselves, trojans pretend to be useful, ransomware locks files for payment, spyware records activity.
Social engineering
Phishing: fake emails or texts to steal details. Shouldering and blagging trick people into giving access. People are often the weakest point.
Technical attacks
Brute force: trying every password. Denial of service: flooding a server so real users cannot get in. Data interception: capturing data in transit. SQL injection: malicious SQL typed into a form to read or change a database.
Prevention
Penetration testing (ethical hacking to find weaknesses), anti-malware, firewalls (filter traffic), strong passwords and regular changes, user access levels, encryption (scrambles data so it is unreadable without the key), physical security and staff training.

Exam tip: For 'explain' questions, name the threat, say how it works, then how to stop it.

2.1 Algorithms

Computational thinking
Abstraction: remove unnecessary detail. Decomposition: break a problem into smaller parts. Algorithmic thinking: work out the steps to solve it.
Showing algorithms
Flowcharts: oval = start/stop, rectangle = process, diamond = decision, parallelogram = input/output. Pseudocode and OCR Reference Language are also used.
Linear search
Checks each item in turn. Works on unsorted data but slow on long lists.
Binary search
List must be sorted. Check the middle, discard the half that cannot contain the item, repeat. Much faster.
Bubble sort
Compare neighbouring items, swap if out of order, repeat passes until no swaps are made.
Merge sort
Split the list down to single items, then merge them back in order.
Insertion sort
Take each item and insert it in the right place in the sorted part.
Trace tables
Record the value of each variable step by step to predict output or find errors.

Exam tip: Be able to complete, correct and write algorithms, not just describe them.

Binary search code

found = False
low = 0
high = list.length - 1
while low <= high AND found == False
    mid = (low + high) DIV 2
    if list[mid] == target then
        found = True
    elseif list[mid] < target then
        low = mid + 1
    else
        high = mid - 1
    endif
endwhile

Bubble sort code

do
    swapped = False
    for i = 0 to list.length - 2
        if list[i] > list[i + 1] then
            temp = list[i]
            list[i] = list[i + 1]
            list[i + 1] = temp
            swapped = True
        endif
    next i
until swapped == False

2.3 Producing robust programs

Defensive design
Plan for misuse. Authentication checks who the user is. Input validation checks data is sensible: range, length, type, presence, format. Validation does not prove data is correct. Sanitise inputs to remove harmful content.
Maintainability
Comments, indentation, meaningful variable names, subprograms and constants make code easier to read and update.
Testing
Iterative testing happens during development, final testing at the end. Syntax errors break the language rules. Logic errors run but give wrong results.
Test data
Normal: valid, expected. Boundary: on the edge of what is allowed (valid values right on the edge, e.g. 0 and 100 for a range of 0-100). Invalid: should be rejected. Erroneous: wrong type, like text in a number field.
Refining
Use test results to fix errors and improve the program.

Exam tip: Boundary data always comes in pairs: the last valid value and the first invalid one.

Boolean logic works with True/False (1/0). In OCR notation, inputs are letters such as A, B, C and the output is Q.

Method

  1. Count inputs. n inputs gives 2n rows (2 inputs = 4, 3 inputs = 8).
  2. List all input combinations by counting in binary.
  3. Add a column for each gate, working left to right through the diagram.
  4. The last column is Q.

2.5 Programming languages and IDEs

High-level
Human-readable, one statement becomes many machine instructions, portable between machines, easier to write and debug. Needs translating.
Low-level
Machine code (binary) and assembly. Close to the hardware, fast and memory-efficient, but hardware-specific and hard to write.
Compiler
Translates the whole program to machine code in one go. The result runs fast without the source, but errors are reported afterwards.
Interpreter
Translates and runs line by line, so it stops at the first error, which helps debugging, but runs slower and needs the source each time.
Assembler
Translates assembly into machine code. OCR says understanding assemblers is not required, so focus on compilers and interpreters.
IDE tools
Code editor, error diagnostics, run-time environment, translator, plus debugging: breakpoints, stepping through code and watching variables.

endif
